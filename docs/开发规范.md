# FlowMint 开发规范

本文件是项目的强制规范，所有代码与文档改动都必须遵守。

## 1. 目录与文件组织

- **按职责分类存放**：实现文件必须放进清晰的子目录/子模块，**禁止**把大量实现直接堆在一级 `src/` 下。
  - Rust：workspace 的 crate 划分本身即职责划分；crate 内保持惯用的模块拆分（一个模块一个 `.rs`），不为拆而深套。
  - 前端：`components/`（UI 组件）、`lib/`（无 UI 的逻辑/封装），入口 `main.tsx`、根 `App.tsx`、全局 `styles.css` 允许在一级。
  - CLI：`cli.rs`（命令定义）+ `commands/`（每个命令一个模块）。
  - SDK：按职责拆模块（如 `rule-engine.mjs` / `http.mjs`），`index.mjs` 只做汇总导出。
- 目录结构与各子项目职责见 [目录结构与子项目](目录结构与子项目.md)。

## 2. 代码风格

- **优先可读性与可维护性**，逻辑明确直接。
- **禁止为未确认的场景编写兼容、兜底、冗余逻辑**。只实现当前确认的需求。
  - 例外：网络层对**不可信输入**（畸形字节、异常协议）的必要健壮性属于已确认需求，不算兜底。
- 发现死代码（未使用的函数、依赖、模块）应立即删除，不保留"以后可能用得上"的代码。
- **必要处加注释**：解释"为什么"而非复述"做了什么"；公共 API 加文档注释。
- 代码注释语言：现有 Rust 库代码（`crates/`）沿用英文文档注释以保持一致；应用层面向使用者的输出、前端、SDK 与全部项目文档使用中文。

## 3. 文档

- **全部项目文档使用中文**。
- **根 `README.md` 是文档入口**，必须索引到所有重要子文档。
- **新增/删除/改名文档时，必须同步更新根 `README.md` 的文档导航。**
- 当**架构、接口、项目规范、构建流程或运行流程发生变化**时，必须及时更新相关文档（至少：本规范、[目录结构与子项目](目录结构与子项目.md)、[构建与运行](构建与运行.md)、必要时 README）。

## 4. Git

- **提交信息使用中文**，说明这次改动做了什么、为什么。
- 一次提交聚焦一件事，避免把不相关改动混在一起。
- 不提交捕获到的流量数据、构建产物、`node_modules`、密钥/证书私钥（见 `.gitignore`）。

## 5. 验证

改动后至少通过对应验证再提交：

- Rust：`cargo build --workspace` 与 `cargo test --workspace` 无错。
- 前端：`npx tsc --noEmit` 类型检查通过。
- 桌面应用：`npm run tauri build -- --no-bundle` 能出可运行的独立 exe（**不要用 `cargo build`**，详见 [构建与运行](构建与运行.md)）。
- 多语言 SDK：先 `cargo build -p flowmint-ffi`，各语言绑定的验证见 [多语言 SDK 开发](SDK开发.md)。
